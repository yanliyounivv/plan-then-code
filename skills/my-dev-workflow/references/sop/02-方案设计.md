# 阶段② 方案设计 SOP

> 本阶段的唯一目的：**产出一份能直接照着写代码的计划**。计划是图纸，不是归档材料——衡量标准是"拿着它能不能逐条把代码写出来"。

## 准入（Entry）
- ⓪ 的计划已获用户确认（含理解复述与范围边界，见 `01-需求澄清.md`）。这是全流程第二次也是最后一次确认门。

## 固定动作（按顺序）

1. **给方案**：2~3 个方案，每个含优劣 / 成本 / 推荐项，等用户拍板。涉钱/资质/合规/发布/删数据**永不自决**。
2. **定契约**：用户拍板后，定下技术选型、表结构、状态机、接口契约——这些是编码时实际要照着写的，不是摆设。
3. **拆任务清单（核心产物）**：把方案拆成编号任务 T1…Tn，每条必须写清三件事：
   - **做什么**（一句话，具体到文件/模块/接口）
   - **验收点**（这条做完怎样算过：哪个验证命令、什么现象）
   - **依赖**（依赖哪条任务，能并行就标可并行）
   
   模板：
   ```
   T1 建 users 表 + 索引 ｜ 验收：db migrate 通过、字段对齐契约 ｜ 依赖：无
   T2 注册接口（controller+service+model）｜ 验收：接口实测返回 200 ｜ 依赖：T1
   T3 状态机中文枚举表 ｜ 验收：五方字段一致 ｜ 依赖：T1，可与 T2 并行
   ```
4. **重要决策记 ADR**：仅当涉及选型/架构/付费/迁移等不可逆决策时写（一句话到半页即可），普通决策不写；ADR 在任务完成时统一落盘。

## 准出（DoD）
- [ ] 方案被用户拍板
- [ ] **任务清单 T1…Tn 存在，每条有"做什么 + 验收点 + 依赖"**
- [ ] 编码要用的契约（表结构/状态机/接口字段）已定稿
- [ ] 不可逆决策已写 ADR

> 注意：准出卡的是"计划能不能指导编码"，**不是**"文档写得多齐全"。

## 收尾（文档在任务完成时统一更新）
- 计划存哪由用户定；若项目已用 `docs/`，方案放 `docs/02-方案/`、ADR 放 `docs/02-方案/ADR/`。
- 本阶段不单独记流水；方案文档与 ADR 在任务完成时统一归档到位。
- 文件地图在任务完成时按实际变更统一更新。

## 触发口令
| 用户说 | 动作 |
|---|---|
| "先设计不写代码 / 只给报告 / 只输出任务拆解表" | 只出设计 + 任务清单，绝不写代码 |
| "细化 M1 / 按编号执行" | 把该里程碑拆到 T1…Tn，交③执行 |
