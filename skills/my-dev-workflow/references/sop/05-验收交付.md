# 阶段⑤ 验收交付 SOP

## 准入（Entry）

- 审计问题（P0/P1）已关闭。

## 固定动作（按顺序）

1. **截图对比**：UI 改动必须截图改前/改后对比。
2. **实测取证**：证据三选一必给——接口实测输出 / 构建测试通过 / 页面截图。
3. **标注分级**：每个功能标【真实现 / 占位 / 演示数据】。
4. **契约五方对齐**：前端调用 ↔ 前端字段 ↔ 后端返回 ↔ 数据库字段 ↔ 后台可操作。
5. **写交付说明**：按 `my-dev-rules/references/交付规范.md` 的「交付汇报结构」逐段写（结论 → 做了什么 → 证据 → 已知问题 → 待决定的事），结构不在本文件重复定义。

## 准出（DoD）

- [ ] 证据三选一已给
- [ ] 契约五方对齐
- [ ] 真实现/占位/演示已标注
- [ ] 多端主链路跑通（如涉及三端）

## 收尾（文档在任务完成时统一更新）

- 验收的产出是**上面那份交付汇报**，直接给用户看，这是主产物。
- **任务完成时**：UI 截图对比按用户需要归档到 `docs/06-验收/`；日志补记验收阶段流水；文件结构有变才更新地图。
