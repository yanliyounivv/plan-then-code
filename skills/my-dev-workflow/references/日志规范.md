# 日志规范

> 定位：日志与相关文档在**对话结束、任务完成时统一更新到位**。编码过程中靠对话逐条汇报保持进度透明，不边写边补文档；但收尾时该更新的文档（日志 / 文件地图 / 契约 / 流程图 / ADR）必须全部更新、记录补齐，不许只写一条流水就交差。

## 三层日志

| 层 | 对象 | 位置 | 粒度 |
|---|---|---|---|
| 过程日志 | 任务完成时的关键结果 | `docs/日志/YYYY-MM-DD.md` | 按阶段 / 批次，该记的都记 |
| 问题追踪 | 每个缺陷 / 问题 | 同文件内问题追踪表 | P0/P1 每问题一行，P2/P3 按需 |
| 决策记录 ADR | 重要技术决策 | `docs/02-方案/ADR/ADR-XXX-标题.md` | 每决策一篇 |

## 唯一口径（全系统只认这一个）

```
docs/日志/YYYY-MM-DD.md    ← 一天一个文件，append，不覆盖
```

- 不要写成 `docs/2026-11-24-发布页改造.md`（放 docs 根、按事件命名）——那是旧口径，已废弃。
- 同一天多个任务 → 追加到同一个文件，按阶段分段。
- 日志"一天一个"与"按事件命名"二选一，**只选日期**，因为事件已由「事项」列表达。

## 模板

两张表 + 文件头部的字段定义**只在** `assets/日志模板.md` 一处维护，本文件不复制表头。
ADR 字段只在 `assets/ADR模板.md` 一处维护。

## 任务完成时统一更新清单（逐项过，发生了的必须更）

- [ ] `docs/日志/YYYY-MM-DD.md`：工作流水按阶段补记 + P0/P1 问题追踪表
- [ ] 文件有增删 / 改用途 → 更新 `docs/00-项目总览.md`
- [ ] 状态机 / 接口契约有变动 → 同步契约文档与流程图
- [ ] 不可逆决策（选型 / 架构 / 付费 / 迁移）→ 补 ADR
- [ ] 用户要归档的方案 / 审计报告 / 验收截图 → 放 `docs/` 对应目录

> 没发生的项不动，不为凑数制造文档；发生了的项不许漏。

## 日志铁律

1. **任务完成时统一更新**：单条任务完成靠对话汇报；对话结束 / 任务完成时把该更新的文档和记录一次性补齐，不许只记一条流水，也不许遗漏。
2. 一天一个文件，append 不覆盖；留空列就留空，没发生的不用硬填。
3. 执行者 / 发现者 / 解决者**如实填写**，不许糊弄。
4. 切换智能体后，接手方先读上一段「执行者 + 遗留」列再继续。
5. 状态用中文：待处理 / 进行中 / 已完成 / 已归档 / 已关闭。
6. 所有表格纯 MD，可 grep / 脚本统计。
7. 确实没有任何变更才跳过当天日志；有变更就必须记。
