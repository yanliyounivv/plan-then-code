## 列定义

| 列 | 说明 |
|---|---|
| 路径 | 相对项目根的路径，用 ├/│ 缩进表达层级 |
| 类型 | 入口/逻辑/视图/组件/服务/目录/文档/图/契约/配置 |
| 用途说明 | 一句话写清这个文件是干嘛的 |
| 对应代码/契约 | 图和文档绑定的真实代码位置（防止漂移） |
| 状态 | 活跃/遗留/待删/已归档/待确认 |
| 版本 | 文档/图用，代码可用 git 代替 |
| 最后更新 | 日期 |
| 更新人 | 谁改的（产品+模型） |

## 铁律

1. **只在文件结构真的变了才更新本表**（增删文件、改用途、改状态）；只改了文件内容不动结构，就不必更新，绝不为此中断编码。
2. 「状态」列：不确定删不删的标「待确认」，不硬删。
3. 本表替代「遗留代码清单」，二者合并为一。
4. 更新后必须与磁盘真实文件核对一致（不一致 = 未完成）。
5. 树状层级用 `├`、`│`、`└` 表达，纯 MD，可 diff。
6. 核对时树状子行只有文件名，要按上一行的目录还原完整路径再比对；**地图自身也必须在表里**（曾漏列 `00-项目总览.md`，靠核对脚本抓到）。
