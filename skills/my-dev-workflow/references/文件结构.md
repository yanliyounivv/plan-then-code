# 文件结构规范

## 统一目录（所有项目一致）

```
项目根/
├── README.md              ← 项目总览 + 启动方式 + 目录说明
├── docs/                  ← 可见，绝不用 .docs
│   ├── 00-项目总览.md      ← 项目文件结构地图（树状表）
│   ├── 01-需求/
│   ├── 02-方案/
│   │   └── ADR/           ← 架构决策记录
│   ├── 03-契约/            ← 接口契约、表结构、状态机、数据字典
│   ├── 04-开发/            ← 里程碑、实现说明
│   ├── 05-审计/            ← 评审报告、问题清单
│   ├── 06-验收/            ← 测试报告、验收记录、截图
│   ├── 07-上线/            ← 上线清单、部署、合规、回滚
│   ├── 日志/               ← YYYY-MM-DD.md
│   ├── 图/
│   │   ├── 状态机/
│   │   ├── 流程/
│   │   ├── 架构/
│   │   └── 时序/
│   └── 协议/               ← 隐私政策、用户协议、合规
├── 代码目录（pages/cloudfunctions/services/... 按技术栈）
└── 工具链点文件          ← .gitignore / .env.example / .eslintrc.js 等，见下方例外
```

## 铁律

1. **任何业务文件、业务目录都不许 `.` 开头**。例外仅限工具链必需项：`.gitignore`、`.git/`、`.github/`、`.workbuddy/`（项目记忆，禁止删除）、`.env.example`、`.eslintrc.js`、`.eslintignore`、构建工具的 `admin/.env` 等；这些不计入业务文件。
2. 文档目录统一 `docs/`（不是 `.docs/`）。
3. **同一目录内命名风格必须一致**：`日志/` 固定 `YYYY-MM-DD.md`；其余目录用 `[内容].md`（阶段已由目录表达），需要强调阶段时用 `[阶段]-[内容].md`。同一目录内不许日期型与主题型混用。
4. 文档与 SOP 阶段对齐：确实要留存的文档，按所属阶段进对应目录；不留存就不建空目录。
5. 代码目录遵循各技术栈标准（小程序/云函数/Vue/FastAPI），不自定义。
6. 先有代码成果、后有文档归档：不许为了填满本目录结构而提前创建或编造文档。
