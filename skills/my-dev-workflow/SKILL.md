# 我的开发工作流

一句话定位：**按计划写代码，不是按代码写 md。**

主产物是**跑得起来的代码**；计划是驱动代码的图纸；文档在**任务完成时统一更新到位**——该更的都更、该记的都记，不许只记一条流水了事；但也不边写代码边补文档，不为了凑数制造文档，更不拿文档当进度证据。

> 与 `my-dev-rules` 的分工：本 skill 管**顺序**，规则库管**质量**。冲突时的优先级见 `my-dev-rules` 的「规则优先级」。

## 五条流程铁律（编号用于回指，违反即返工）

| 编号 | 铁律 | 一句话判定 |
|---|---|---|
| W01 | **入口门禁** | 没出计划、没等到确认，一行代码都不写 |
| W02 | **逐条推进** | 按 T1…Tn 一条一条写、验、报；**同一条连续失败 2 次必须停下汇报，禁止第 3 次盲试** |
| W03 | **阶段门禁** | 每阶段有准入/准出（DoD），不满足不进下一阶段 |
| W04 | **收尾补齐** | 任务完成时统一更新该更新的文档与记录，不遗漏、不凑数 |
| W05 | **停下等指令** | 交付/上线/提交一律等用户明确指令，不自作主张 |

> W03 卡的是「计划与代码是否到位」，不是「文档是否写齐」。判进度、审计、排错一律看磁盘真实代码（`R02`）；修一处扫同类（`R03`）本文件不重复。

## 边界与越界（能力黑名单）

**只做**：计划推进、按编号执行、交接上下文、日志与文件结构管理、流程图。
**不做**：纯问答/翻译/闲聊 · 选型与代码写法（→ `my-dev-rules`）· 排期报价与人力估算 · 代替用户决定涉钱/资质/合规/发布的事。

越界时一句话交代：**「这归 X 管，不走本流程」**，不硬接、不假装能做。

## 主线（全系统唯一一处画全套流程）

```
任务到手
 → ⓪ 接任务三问 + 出计划 + 复述理解（目标范围 / 阶段顺序 / 验收点 / 待确认点 / 风险）
 → 用户确认（一次性；说「先列需求 / 不改代码」就停在设计层）
 → ② 方案拍板 + 拆 T1…Tn（做什么 / 验收点 / 依赖）
 → ③ 按编号逐条写代码 → 每条写完当场验证 + 汇报
 → ④ 审计复查（P0–P3）→ ⑤ 验收交付 → ⑥ 上线发布（等指令）
 → 收尾：横向扫同类 + 统一更新 md（日志/地图/契约/流程图/ADR）
 → 停下等用户决定：提交 / 上线 / 继续
```

## 任务接收契约（⓪ 之前必须知道的三件事）

| 必须知道 | 缺了怎么办 |
|---|---|
| **1. 目标端**：小程序 / Web 后台 / 后端 / 原生 App / 单文件 | 问一句，别猜 |
| **2. 代码范围**：哪个项目、哪个目录、动哪些文件 | 不给就自己看目录 |
| **3. 验收方式**：截图 / 接口实测 / 构建通过 | 默认构建+截图；UI 必须截图 |

三件都缺 → 一次问齐再出计划；只缺一件 → 标【待确认】写进计划，不阻塞其余推导。
**不许拿"我以为"当输入**——不确定就写进「待确认点」，让用户一次补齐。

## 何时触发

拆计划、排执行顺序、按编号推进（"列计划 / 按编号执行 / 继续往下做 / 细化 MX / 先设计不写代码"）· 交接上下文 · 记开发日志、更新文件地图、整理文件结构、画流程图。

不触发：纯问答、翻译、闲聊、"这段代码怎么写才对"（归 `my-dev-rules`）。

## 阶段说明

| 阶段 | 干什么 | 硬要求 |
|---|---|---|
| ⓪ 入口门禁 | 三问 + 计划 + 复述理解 | **只有这一次确认**；需求模糊按 `sop/01` 追问，仍在这同一次里 |
| ② 方案设计 | 2~3 方案拍板 + 定契约 + 拆 T1…Tn | 每条带「做什么 + 验收点 + 依赖」，否则不算完成 |
| ③ 编码实现 | 逐条写、当场验、当场报 | 没过验收点不进下一条；失败 2 次必停（`W02`） |
| ④ 审计复查 | 真实代码 + 契约三方对照 + P0–P3 | P0/P1 清零才进⑤；修复循环同一问题最多 3 轮 |
| ⑤ 验收交付 | 证据三选一 + 五方对齐 + 分级标注 | 结构见 `my-dev-rules/references/交付规范.md` |
| ⑥ 上线发布 | 上线前清单 + 回滚路径 | 部署/发布等用户明确说 |

确认门只有两处：⓪ 计划、② 拍板。小改动计划已明确可直接进③；纯设计停在②。
