# 最痛的教训（复犯即失信用）

> 以下是我真正发过火、或让你返工最多的场景，**一次都不许再犯**。每条都带真实案例，案例是规则的灵魂，不是冗余。

1. **没理解就动手**。模糊的 UI/需求指令，必须先复述你的理解和思路，我说"确认"后才动手。
   - 真实案例：我说"去掉底栏上面的灰色"，你理解成改底栏颜色，来回三轮才对齐；刘海 App 热区点击位置你猜错两次。

2. **只看文档不看代码**。审计、进度评估、问题排查，**必须基于磁盘上的真实代码**，文档往往是过期的。
   - 真实案例：我说"你不要只看文档确定，你去看代码，有很多都没做"；"我让你检查遍代码，你别去找这些文档看"。

3. **修一处不查同类**。修完一个问题必须横向扫全项目同类问题，一次性汇报一起修。
   - 真实案例：位置字段断链一处修完后，全项目扫出 16 处同变种；头像上传只改个人页，管理员端读者档案、读者详情、借阅选人三处都没读 `avatarUrl`。

4. **重复让我给已给过的信息**。我给过的参数、截图、报错、账号，不许再要第二遍。

5. **在原地空想不行动**。缺插件、缺方案就自己去找去试，别"想来想去"。
   - 真实案例："你用什么插件就自己去找行不行，别在这里想来想去"。

6. **把占位/演示当真实现汇报**。是占位就说占位，是假数据就说是假数据，没验证就说没验证。

7. **把环境噪音当业务缺陷**。IDE 单文件诊断、开发者工具对比度误判、基础库内部报错、离线节流断网，先判定性质再动手；不要为工具误报改业务代码，也不要拿它当"问题已修复"的成果。

8. **启动完不验证**。只说"已启动"不行，要验证端口、健康检查、主链路。服务还必须后台驻留，不能随 shell 会话退出。
   - 真实故障：我"连不上"就是因为进程跟着 shell 退了。

9. **拿"文件一致"当结论**。文件 md5 逐字节相同 ≠ 渲染正确；界面错位要看 CSS 层叠/布局机制，拿"和原项目一样"搪塞会被直接否掉。
