# 产品与体验偏好

## 1. 参考主流，不自创

- UI/交互拿不准就参考成熟产品：转转/交易猫（交易闭环、担保感、竞价体验）、淘宝（商品详情/店铺）、美团（列表筛选/消息中心）。
- 用户说"按淘宝/美团这类做"就是直接对标，不用再设计。
- 不要发明新交互范式，尤其别为"有设计感"牺牲可理解性。

## 2. 文案简洁

- 界面提示语短而准："请选择磨料品类"就够了，**不要"先选大类再选品类"式的啰嗦引导**。
- 提示语要给出可执行的下一步（"后端未配置，请先在 env.ts 填云环境地址"），不是丢底层错误码。
- 汇报也说重点，长调研压成几百字，不要刷屏。

## 3. 商业化质感，拒绝 Demo 感

- 用户评价标准："不够商业化，像个小 Demo""不够大气""束手束脚"。
- 细节必查：文字截断/重叠、留白均匀、按钮大小比例与样式统一、按钮居中或靠边一致性、图片占比（商品页以图为主，主图不能小）。
- 还要看：色彩层次（底色/卡片/分隔/强调四层）、空状态/加载态/失败态都要有设计，不能白屏、不能"点了没反应"。
- 数字用等宽（`tabular-nums`）；后台/数据页优先表格与横向数据带，不要一排大卡片浪费屏宽。

## 4. 无假数据（高频红线）

- 原话："我不排斥测试数据，但是我不要假数据。你的所有数据都必须在后台传输过。"
- 测试数据规则：**必须有规律、必须入库、必须走真实接口链路**；需要图片就按关键字下载真实图片（不商用），按业务图片同方式存储。
- 演示痕迹必须清除：写死的假时间、假电量、假定位、假 ID 兜底、假头像、假统计、写死倒计时、"共 1284 条"这类数字，一个不留。
- 前端不许自己编列表兜底（`|| [默认数据]`），接口空就展示空状态。
- 运营数据（成交播报、排行榜、热搜、行情）必须后端真实打通，后期后台可管理（隐藏/置顶/补录）。

## 5. 无死按钮、无断流程

- 每个按钮必须有真实后续：真调接口、真跳转、真写库。只弹 toast 不干活 = 假按钮。
- 入口必须有完整流程："发起 → 详情 → 流转 → 完成 → 可回看"。
- 交付前自查："这个页面有多少按钮点进去后面没有页面或没有功能？"
- 表单校验前后端都要有，只在前端校验等于没校验。

## 6. 前后端契约一致

- 用户会专门查"前端有字段、后端无功能"和"后端有字段、前端没渲染"，交付前自己先对齐五方：
  `前端调用 ↔ 前端渲染字段 ↔ 后端实际返回 ↔ 数据库字段 ↔ 后台可操作（权限点/路由/按钮）`。
- 历史高频断点（逐条查）：详情页 `timeline/product/seller/counterparty/canReview`；列表 `counterparty/source`；图片字段（`images` vs `imageUrls`）；收藏/浏览时间（`favoritedAt` vs `createdAt`）；金额分/元；状态枚举；权限点；未注册路由（点了必 404）。

## 7. 状态与文案

- 状态一律中文（待审核/已接受/已过期/已归还），禁止 pending/accepted 直接给用户看。
- 状态 → 中文 → 颜色做成一张枚举映射表，全端共用，不许每页各写一份。
- 收藏这类交互：图标变化（五角星变黄），不是把字换掉。

## 8. 表单与发布流程：只减不增

- 能自动生成/自动核验/自动带出的字段，一律不让用户填（标题、等级、镇区、时间、单位）。
- 自动生成的不留输入框；能获取一次的就一个框；联系电话默认带出但可改。
- 必填项要真有必填校验（定位/电话/图片/现场情况缺一不可）。
- 发布类页面每加一个字段都要有理由，默认是减字段。
- 弹窗/表单别让用户纵向滚动才能填完：加宽、改多列、分组。

## 9. 适配

- iPhone 底部安全区 `env(safe-area-inset-bottom)` 必须处理；底栏布局要经真机验证。
- 自定义底栏高度、悬浮元素遮挡是反复踩的区域，改完必须截图对比。
- `viewport-fit=cover` + `100dvh`（不写死 `100vh`）；输入框字号 ≥16px 防 iOS 聚焦放大；`touch-action: manipulation` 消除点击延迟；点击区域 ≥44px。
- 至少实测 320 / 390 / 1440 三个宽度，确认无横向溢出；窄屏允许换行，不许挤压成竖排文字。

## 10. 列表与检索类交互

- 搜索：搜索历史/热门搜索/排行榜都要真实后端；搜索结果页直接展示结果，不顶着一层历史记录。
- 筛选：筛选条件以胶囊形式显示在结果区上方，可点叉移除并实时联动。
- 排序：点价格出排序面板（抽屉），支持重量/收藏/浏览量等业务维度。
- 分页：服务端分页 + 触底加载 + 下拉刷新，不许一次拉全量再前端切页。
- 选中态：全站统一（如整行黑底白字），悬停浅色、选中深色。
- 消息：角标数量要真实，"全部已读"入口要有。
- 后台：要地图/图表等可视化（注册地区分布、货源区域分布），不要只有表格。

## 11. 品牌与图标

- 品牌统一：logo、名称、主题色调全套一致。改名时全站搜：标题、文案、水印、页脚、分享卡片、后台登录页、打包配置。
- 图标语义要贴切（每日行情用统计图图标），图标缺失/不显示是 bug。
- **禁止用 emoji 当图标**（真实原话：一页 13 个 emoji，反 AI 审美，不达标）。
- 多端样式基线用 token（颜色/字号/间距/圆角），**业务组件禁止裸色值**，只有 token 文件与必要导航色可写死。

## 12. 视觉方向（默认审美）

默认走"工业/专业、克制、可信"路线（Impeccable 风）：

- 深蓝灰基底 + 单一强调色（工业赭橙），明暗分区建立层级；状态色降饱和，只在需要决策处用强调色。
- 中文系统字体栈，靠字重/字距/字号做层次（避免默认 Inter/Roboto 的泛 AI 感）。
- 数据密集但呼吸有序：横向数据带 > 一排等宽卡片；分组侧边栏 > 一长列菜单。
- **明确反参考**：紫蓝渐变、霓虹发光、玻璃拟态堆叠、圆润可爱的消费级二手风、深色科技 dashboard 发光风。

## 13. 原型 / 设计稿落地

- 原型不是代码模板：CSS 原子类、内联 SVG、模板里调函数、写死倒计时、演示数字、默认已勾选协议，一律不能直接搬进生产。
- 原型与后端不一致时以真实代码为准（状态枚举、节点数、接口缺口），先列差异清单再动手。
- 原型里缺接口的页面（收藏列表、浏览足迹等）明确二选一：补后端，或先本地缓存并标注，不许假装打通。

## 14. 重要改版先看方案

- 重要 UI 改版前，先给多个风格方案对比（用户选过 Impeccable 风格，也用过小米 MiMo 式浅米白底 + 黑白灰 + 小圆角）。方向定了再落代码。
- 关键界面可多视角评审（Impeccable / TDesign / Skyline 各出意见）再收敛。
- 评审意见落到"哪个页面哪一块怎么改"，不泛泛说"可以更美观"。

## 15. 数据、隐私与审核（红线）

1. **位置分级**：强制采集但分级展示。公开只到市/镇一级；详细地址、经纬度永不下发普通用户，仅管理端可见（管理端地图可视化用精确点位）。
2. **图片 EXIF 防泄露**：原图私有存储仅审核可见；展示图去 EXIF、必要时遮挡门牌招牌。
3. **人工审核**：商品图与商品信息全量人工审核（量小），未过审不进集市/搜索/店铺/行情样本；资料变更需重新审核。
4. **敏感词打标不拦截**：命中后进人工队列，不自动封。
